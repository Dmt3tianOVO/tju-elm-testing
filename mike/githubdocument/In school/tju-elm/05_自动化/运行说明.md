# 05_自动化 运行说明（成员C）

> 对应任务卡《04_成员C_自动化.md》。两条 Selenium 自动化用例复用 **TC-01**（登录）、**TC-03**（商家菜品）；
> 外加一个证据工具 `branch_probe/observe_branch.py`，用于 `Login.vue` 第 83 行 `if (!user)` 单判定的双分支运行观察。
> **不**包含 POM / Allure / CI，不声称整站覆盖率。

## 1. 前提条件

1. 后端已启动：`http://localhost:8080`（Spring Boot，`src/elmboot`，基线仓库 `8efcb99`）。
2. 前端已启动：`http://localhost:8084`（`src/elmclient`，`vue.config.js` 端口 8084；登录请求直连 8080，后端已放行 CORS，无需 proxy）。
3. MySQL `elm` 库种子数据在位：
   - 账号 `19112121212` / `123456Qaq`（userName=JAVA爱好者，delTag=1）；错误密码分支使用 `Wrong123`（后端 HTTP 200 空响应体，属正常业务拒绝）。
   - 商家 `10001`「万家饺子（软件园E18店）」（orderTypeId=1 美食类）；菜品 foodId=1「纯肉鲜肉（水饺）」价格 `16.00`。
4. 已安装 Chrome 浏览器及版本匹配的 ChromeDriver。

## 3. 准备依赖（一次性）

在**项目根目录**（`tju-elm/`，即本 `05_自动化/` 的上一级）执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r 05_自动化\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> Chrome 128 对应驱动下载地址（本机实际使用）：
> `https://storage.googleapis.com/chrome-for-testing-public/128.0.6613.138/win64/chromedriver-win64.zip`，
> 解压后将路径指向 `chromedriver.exe`：
> `$env:CHROMEDRIVER_PATH="C:\路径\chromedriver-win64\chromedriver.exe"`

## 4. 运行命令

从项目根目录执行（任务卡示例命令，已实测通过）：

```powershell
python -m pytest 05_自动化/test_smoke.py -q
```

两轮干净会话重跑（本机实际执行，证据分别归档）：

```powershell
$env:CHROMEDRIVER_PATH="C:\Users\admin\.local\drivers\chromedriver-win64\chromedriver.exe"
$env:RUN_TAG="R1"; python -m pytest 05_自动化/test_smoke.py -v
$env:RUN_TAG="R2"; python -m pytest 05_自动化/test_smoke.py -v
```

每轮收集并执行 **2 个测试**；每个测试均使用独立临时 `--user-data-dir`，会话间不共享 Cookie / sessionStorage。

可选环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ELM_BASE_URL` | `http://localhost:8084` | 前端地址 |
| `ELM_BACKEND_URL` | `http://localhost:8080` | 后端地址（文档说明用） |
| `CHROMEDRIVER_PATH` | 空（走 Selenium Manager） | 显式指定 chromedriver.exe |
| `ELM_HEADFUL` | 空（headless） | 设为 `1` 时打开有界面浏览器，便于演示观察 |
| `RUN_TAG` | `manual` | 证据子目录名（R1 / R2） |

## 5. 断言口径（不能省的部分）

- **TC-01 `test_tc01_login_jump_and_session`**：干净会话先确认未登录 → 在真实登录页输入 `19112121212 / 123456Qaq` 并点「登陆」
  → 显式等待 URL 含 `/index` → 读取 `sessionStorage.user` 并 JSON 解析，断言 `userId == "19112121212"`。
  全程操作真实页面，**未注入 sessionStorage**。
- **TC-03 `test_tc03_business_food_name_and_price`**：自行调用同文件登录辅助函数完成登录 → 进入美食类商家列表
  (`/businessList?orderTypeId=1`) → 断言列表存在「万家饺子（软件园E18店）」并点击 → 详情 URL 含 `businessId=10001`、
  `h1` 为该商家名 → 在 `ul.food` 中定位「纯肉鲜肉（水饺）」所在的同一个 `<li>`，**价格断言限定在该 li 内**。
  接口返回数值 `16.00`，JSON 数字被 JavaScript 解析后丢失尾零、页面渲染为「¥16」，
  故脚本按数值相等断言 `Decimal("16") == Decimal("16.00")`，而不是全页面出现 16 即算通过。

## 6. 判定覆盖观察工具（不计入主用例）

```powershell
python 05_自动化\branch_probe\observe_branch.py
```

通过 CDP 在页面 JS 执行前注入 XHR 记录探针（不改业务源码、不注入登录态），分别用正确密码与 `Wrong123` 走真实登录，
在页面 JS 上下文中还原 `response.data` 并对 `Login.vue:83` 的 `!user` 求值，记录条件值、HTTP 状态、响应体、
分支效果（跳转/弹框）与截图。结果写入 `evidence/branch/branch_observation.json`，两分支均命中时退出码 0。
